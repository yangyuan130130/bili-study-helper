# B站学习进度助手

一个 Tampermonkey 油猴脚本，在 B 站视频页实时显示**当前小合集还剩几集、还要学多久**。

面向的典型场景：看有着大量分集的教程类合集，想知道「这门课还剩多少小时才能学完」。

## 它解决什么问题

B 站自己的合集进度只显示「已看 X / 共 Y」，不告诉你**剩余总时长**，也不会因为你是跳着学而调整口径。这个脚本补上这一块：

- 大字号显示剩余待看时长（小时 + 分钟）
- 显示待看集数 / 已完成集数 / 总集数
- 进度条 + 已完成时长
- 分集列表只列**还需要看**的集，跳过的不再打扰你

## 统计口径：起点自动推断

脚本不提供「标记已看」这类手动操作，全部由播放行为自动判定。

```
起点 S = 最早有播放证据的那一集（与当前页取更靠前的）
i < S  → 一律视为已完成（被主动跳过），不计入剩余
i ≥ S  → 只有播到 95% 才算已完成
剩余   = Σ(起点及之后未完成的集时长) − 当前集已播秒数
```

举例：合集共 10 个视频、每个 1 小时，你从第 9 个开始看 → 前 8 个自动记为已完成，剩余待看 **2 小时**（第 9、10 集）。

起点怎么来：

| 来源 | 说明 |
| --- | --- |
| B 站观看历史 | `history/cursor`，`progress > 0` 的集视为播过，取最小下标。未登录会自动降级 |
| 播放观测 | 面板监听到 `playing` 事件且 `currentTime ≥ 3 秒`，把当前集确认为起点并写入本地 |
| 已落盘起点 | 一旦写入就以它为准，**不再回退** |

为什么起点不能回退：否则你回看第 2 集时，第 3~8 集又会变回待看，数字会来回跳。起点只认「本轮第一次真正开始播放的位置」。

如果推断偏了，**双击面板上的大号数字**可以把当前集重设为起点。

## 统计范围：小合集，不跨章节

以王道 408 这类「大合集 → 多门课 → 每门课多分P」的结构为例：

```
大合集 ugc_season「王道考研408公益课程」
└── 8 个 episode，每个 episode 本身就是一门多P的课
    └── 王道计算机考研 数据结构  BV1b7411N798  104P  30.66h
```

脚本只统计**当前所在的那一个小合集**：

| 分支 | 条件 | 统计范围 | 集标识 |
| --- | --- | --- | --- |
| 多P 视频 | 当前 BV 的 `pages.length > 1` | 本 BV 的全部分P | `cid` |
| 单P + 属于某章节 | 命中 `ugc_season.sections[]` | 该章节的 episodes | `bvid` |
| 番剧 | `/bangumi/play/ep*` | `epList` | `epid` |

不存在「把 8 门课 240 小时全算进去」的问题。

## 安装

一键安装（需先装好 Tampermonkey）：

**https://cdn.jsdelivr.net/gh/yangyuan130130/bili-study-helper@v1.3.1/bili-study-helper.user.js**

> 国内直连 `raw.githubusercontent.com` 通常不通，所以这里用的是 jsDelivr 镜像；同一份文件，内容与仓库一致。若你有代理，也可以用仓库里的 Raw 按钮。
>
> 上面链接固定在 `v1.3.1`。装好之后脚本会自己去 `@latest` 检查更新，升级不用再回来点链接。

手动安装：

1. 浏览器安装 [Tampermonkey](https://www.tampermonkey.net/) 扩展
2. 打开 Tampermonkey 面板 → 「添加新脚本」
3. 粘贴 `bili-study-helper.user.js` 全文 → `Ctrl + S` 保存
4. 打开任意有分集的 B 站视频页，右下角出现面板

也可以直接把 `.user.js` 文件拖进浏览器窗口安装。

脚本头里写了 `@downloadURL` / `@updateURL`，之后发布新版本时，装过的人会在 Tampermonkey 里收到更新提示。

## 使用

- 面板可拖拽，位置和折叠状态会记住
- 点右上角 `−` 折叠成小胶囊，只显示「待看 N 集 · 剩余 Xh」
- 点「待看列表」展开分集清单，自动滚动到当前集
- 跟随 B 站深浅主题自动换色
- 没有分集的普通单集视频不显示面板

## 配置

脚本顶部的 `CFG` 对象，改完刷新页面生效：

| 配置项 | 默认 | 说明 |
| --- | --- | --- |
| `watchThreshold` | `0.95` | 播放进度达到该比例即视为该集已完成 |
| `autoSkipBeforeStart` | `true` | 起点之前的集算已完成。设为 `false` 则严格只统计真正播过的集 |
| `startConfirmSec` | `3` | 连续播放超过该秒数才确认起点并落盘 |
| `historyPages` | `3` | 拉取观看历史的页数（每页 30 条，需登录） |
| `historyTTL` | `300000` | 观看历史缓存时长（毫秒） |
| `debug` | `false` | 设为 `true` 后控制台打印 `[BiliStudy]` 开头的解析日志 |
| `cardWidth` / `edge` / `tickMs` | `268` / `20` / `1000` | 面板宽度、贴边留白、刷新间隔 |

## 已知限制

- 观看历史只能翻到最近约 90 条。学了很久的老课程，早期记录可能已经不在历史里，此时靠「播放观测」逐步积累
- 番剧分集只读页面内嵌数据，没有接口兜底
- UP 主的「系列」（`series_id`）暂不支持，只认合集和多P
- 起点记录存在浏览器 `localStorage`（`bsh:start:` / `bsh:done:`），清缓存或换设备会丢
- B 站是单页应用，切换分集不刷新页面；脚本接管了 `history.pushState/replaceState` 并做轮询兜底来跟着重算

## 排障

面板不出现或数字不对时，把 `CFG.debug` 改成 `true`，刷新页面后控制台会打印解析日志，能区分是「数据源没命中」还是「页面结构变了」。
